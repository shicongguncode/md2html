# MD 转 HTML 小工具规格

Status: ready-for-agent

Type: spec

日期: 2026-11-12

## Problem Statement 问题陈述

我经常写 Markdown，但 `.md` 文件只有在我熟悉的编辑器里才好看。想把它当成品看、发给别人、或者打印时，需要一份带排版的 HTML。现成的转换方式要么要联网、要么样式不能改、要么装一堆东西；每次手动复制一份 HTML 再套样式又太麻烦。

我需要一个放在本机、只给自己用的小工具：把写好的 `.md` 变成一份好看的单文件 HTML，样式固定成我喜欢的样子，断网也能完整显示。

## Solution 解决方案

一个 Python 小脚本加一个可拖拽的 `.bat`。把 `.md` 拖到 `.bat` 上（或跑一行命令），就会在源文件旁边生成同名 `.html`：暖米色纸张风格、左侧吸顶目录、深浅色自动切换、代码高亮、表格和引用排版好；文档里有 Mermaid 代码块时渲染成流程图，图库内嵌，断网可看。

生成的 HTML 是单文件，CSS 和 JS 全部内联，不依赖任何外部资源（字体用系统字体回退）。转换过程完全离线，只在首次准备阶段联网下载一次 Mermaid 库并存到本地。

## User Stories 用户故事

1. 作为文档作者，我想把单个 `.md` 文件拖到 `.bat` 上就得到 HTML，以便不用打开终端。
2. 作为文档作者，我想用命令行一次传入多个文件批量转换，以便整理一批笔记。
3. 作为文档作者，我想输出 HTML 就在源文件旁边且同名，以便马上找到它。
4. 作为文档作者，我想在只转换单个文件时自动用浏览器打开结果，以便立刻检查效果。
5. 作为文档作者，我想批量转换时不自动打开每个文件，以免浏览器被弹满。
6. 作为读者，我想生成的 HTML 断网也能完整显示，以便在没网时阅读。
7. 作为读者，我想深浅色跟随系统、并有一个按钮可以手动切换且记住选择，以便夜里看不刺眼。
8. 作为读者，我想左侧有吸顶目录，以便长文档中随时跳转。
9. 作为读者，我想滚动时目录高亮当前章节，以便知道自己在哪。
10. 作为读者，我想目录只列到二级/三级标题，以便目录保持精简。
11. 作为读者，我想用 `--no-toc` 关掉目录，以便短文版面更干净。
12. 作为读者，我想没有目录时正文变成居中的单栏，以便版面不空一条。
13. 作为作者，我想代码块按语言做语法高亮，且配色和暖色主题协调，以便代码易读。
14. 作为作者，我想行内代码、表格、引用块、分隔线、有序/无序列表都正常渲染，以便直接写 GitHub 风格的 Markdown。
15. 作为作者，我想任务列表渲染成复选框样式，以便用 Markdown 记录待办。
16. 作为作者，我想 Mermaid 代码块渲染成流程图，以便在文档里画流程。
17. 作为作者，我想文档没有 Mermaid 代码块时 HTML 不变大，以便大量文档不浪费空间。
18. 作为作者，我想文档有 Mermaid 代码块时图库直接内嵌，以便断网也能看图。
19. 作为作者，我想用 `--no-mermaid` 时把 Mermaid 代码块按普通代码显示，以便排查渲染问题。
20. 作为作者，我想文档标题取第一个一级标题，没有时用文件名，以便生成的页面标题正确。
21. 作为作者，我想顶部小标显示文件名、页脚显示「由某文件生成 + 日期」，以便知道这份 HTML 的来源。
22. 作为作者，我想图片保持相对路径、要求把图片放在文档旁边，以便 HTML 文件保持小巧。
23. 作为作者，我想过宽的表格能横向滚动而不是撑破页面，以便查看宽表。
24. 作为作者，我想中文长文有合适的行高、字号和字体回退，以便长时间阅读不累。
25. 作为读者，我想在手机宽度下页面自动变单栏、字号略小，以便偶尔用手机看。
26. 作为读者，我想打印时隐藏目录和切换按钮、去掉阴影边框，以便直接打印或存成 PDF。
27. 作为作者，我想标题带稳定锚点，以便把某一节的链接单独分享出去。
28. 作为作者，我想含空格或中文的文件名也能正常转换，以便不用先改名。
29. 作为作者，我想 UTF-8 和 GB18030 编码的 Markdown 都能读，以便处理旧文件和其他工具导出的文件。
30. 作为作者，我想转换失败时看到明确的错误信息（哪个文件、什么原因），以便自己排查。
31. 作为作者，我想同名 HTML 直接覆盖，以便反复迭代时不会堆出一堆副本。
32. 作为维护者，我想页面样式集中在一个模板文件里，以便只改 CSS 就能换风格。
33. 作为维护者，我想命令行只有少量、好记的开关，以便日常不用查帮助。
34. 作为维护者，我想日常转换不依赖网络和额外运行时，以便长期可用。

## Implementation Decisions 实现决策

### 模块划分

- **转换核心**：读入 Markdown、渲染为 HTML 片段、生成标题锚点与目录、对代码块做语法高亮、按需把 Mermaid 代码块转成图容器。对外只暴露一个入口函数，接收文本和选项，返回页面所需的各部分内容。
- **页面模板**：一份完整的 HTML 骨架，样式沿用参考样本（暖米色背景、纸张卡片、左侧吸顶目录、深浅色变量、响应式断点、打印样式）。模板只留少量占位标记：标题、顶部小标、目录、正文、页脚、按需插入的高亮样式和 Mermaid 脚本。
- **命令行入口**：解析文件参数和开关，逐个转换，打印结果路径；失败时输出错误并以非零状态退出。
- **拖拽包装**：Windows 批处理，切换 UTF-8 代码页，把拖入的每个文件交给命令行入口；仅当只拖入一个文件时加自动打开。

### 接口约定

- **命令行参数**：位置参数为一个或多个 `.md` 路径；开关 `--open`（转换后打开浏览器）、`--no-toc`（不生成目录）、`--no-mermaid`（不渲染流程图）。默认值即规格描述的行为。
- **输出路径**：源文件同目录、同名、扩展名换成 `.html`；已存在则直接覆盖。
- **模板占位**：模板只负责布局与样式，不承担 Markdown 解析；样式改动不影响转换逻辑。
- **函数边界**：命令行入口只依赖转换核心的单一入口，核心不读文件、不写文件、不解析命令行，便于替换和测试。

### 技术决策

- Markdown 解析使用 CommonMark 兼容的实现，开启表格、删除线、任务列表；不引入 Obsidian 双链、YAML front matter、Typora 软换行等方言特性。
- 语法高亮在生成阶段完成（服务端渲染），配色自定义为与暖色主题协调的一组颜色，不依赖浏览器端脚本；未知语言按纯文本输出。
- 标题锚点：二级标题生成 `sec-<序号>`，三级标题生成 `item-<序号>`；一级标题作为页面标题，不进目录。
- 目录只收二级、三级标题；滚动高亮逻辑放在页面内联脚本中，和参考样本一致。
- Mermaid 库在准备阶段下载一次、固定在本地资源中；只有文档确实含 Mermaid 代码块时才把它内联进输出 HTML，并初始化渲染。
- Mermaid 图使用中性配色；深浅色切换时图不重新渲染（接受这一限制）。
- 编码读取顺序：UTF-8（含 BOM）优先，失败退回 GB18030。
- 页面标题取第一个一级标题；没有一级标题时取文件名（不含扩展名）。
- 顶部小标使用文件名（不含扩展名），页脚写「由 文件名 生成 · 生成日期（YYYY-MM-DD）」。
- 图片沿用 Markdown 中的相对路径，不内嵌；补一条样式让图片不超出正文宽度。
- 没有目录时，正文改为居中单栏，目录区域不占位。
- 页面内联脚本只用原生 JavaScript，不引入任何框架；主题选择存本地存储，读取失败时静默降级。

## Testing Decisions 测试决策

### 什么算好测试

只测外部可观察行为：给定一份 Markdown 文件，命令行退出码、输出文件是否存在、生成的 HTML 里有哪些结构和文本。不测内部函数、不测具体类名、不测高亮产生的每一层标签。测试应该在内部重写后依然全部通过。

### 测试接缝

只留一个接缝：命令行入口。测试在临时目录写一份 `.md`，调用命令行，读回生成的 `.html` 做断言。不新增其他接缝；拖拽包装单独做一次手工冒烟，不进自动化。

### 测试范围

- 基本转换：标题、段落、列表、引用、表格、分隔线、行内代码、链接都出现在输出中。
- 标题与锚点：第一个一级标题成为页面标题；二级/三级标题生成对应锚点并出现在目录中。
- 目录开关：默认有目录；`--no-toc` 后没有目录、且正文为单栏标记。
- 高亮：带语言的代码块出现高亮标记；未知语言不报错。
- Mermaid：含 Mermaid 代码块时输出中有图容器且内联了库；不含时没有图容器、也没有内联库；`--no-mermaid` 时退回普通代码块。
- 图片：相对路径原样保留，不被改写、不内嵌。
- 文件处理：输出路径与源文件同目录同名；已存在时覆盖；含空格和中文的文件名可正常处理；UTF-8 和 GB18030 编码都能读取。
- 错误处理：不存在的输入文件返回非零退出码并给出可读错误。

### 既有测试先例

项目目前没有任何测试代码或测试框架。采用 Python 标准库自带的测试框架，不引入额外依赖；新增的第一个测试文件即成为该项目的先例。

## Out of Scope 不在范围内

- KaTeX 数学公式、Mermaid 之外的图表库。
- 图片内嵌（base64）、字体内嵌。
- 导出 PDF / Word / 图片。
- Obsidian 双链、callout、YAML front matter、Typora 软换行等方言扩展。
- 文件监听、自动重建、GUI 或本地网页界面。
- 多个 Markdown 合并成一份 HTML。
- 主题配置文件、命令行主题切换。
- 深色模式下重新渲染 Mermaid 图。
- 打包成 exe、跨平台安装脚本、CI 和发布流程。
- 团队共享、多人协作、GitHub / GitLab 托管的转换服务。

## Further Notes 补充说明

- 视觉基准是用户提供的一份参考 HTML（`agent-skills-推荐清单.html`）：暖米色、纸张卡片、左侧目录、右上角主题按钮。实现时整段复用其样式，只增补图片、任务列表、高亮配色、Mermaid 容器四处。
- Mermaid 库版本在准备阶段固定一次并记下版本号；升级需要手动替换本地资源并重跑一次含图样例。
- 字体全部走系统字体回退（Noto Sans SC / 苹方 / 微软雅黑 / 系统 sans-serif），不下载字体；不同机器字形会有差异，属预期。
- 参考样本未实现语法配色和流程图，相关样式为本规格新增。
- 生成日期取本机日期，不做时区换算。
- 样式以后如果不满意，只改模板即可；转换逻辑不需要动。
- 若以后想支持图片内嵌或公式，属于新增能力，应另开规格。
