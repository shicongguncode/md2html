Agent Skills · Kimi Code

15 个能和 mattpocock/skills 互补的 Agent Skills（Kimi Code 版）

核对日期：2026-11-12。星标和最近提交时间取自 GitHub 仓库页；只核对了 README 与目录结构，没有实际安装运行。星标每天在变，装之前建议再看一眼。

mattpocock/skills 已经把「写代码」这条线占满了：grill 对齐、to-spec 写规格、to-tickets 拆票、tdd、diagnosing-bugs、code-review、pr、domain-modeling、research、teach、writing-for-agents。所以下面这份清单刻意不碰这些能力，只补它没管的：把东西做出来、把资料变成结构、以及日常使用时的输出形态和审美。

先看这一节：Kimi Code 怎么认 skill

这是后面所有「怎么装」的依据，来自 Kimi Code 官方文档：

  • 用户级目录（所有项目可用）：
    • D:/AppData/kimi-code/skills/ —— 也就是你的 $KIMI_CODE_HOME/skills/，现在 grill-me、tdd 这些就装在这
    • C:/Users/fjhb/.agents/skills/ —— 通用目录，现在的 web-access 在这里
  • 项目级目录（只对当前项目生效）：
    • 项目根 .kimi-code/skills/
    • 项目根 .agents/skills/
  • 额外目录：config.toml 顶层的 extra_skill_dirs，可以挂一个团队共享目录
  • 每个 skill 一个文件夹，里面必须有 SKILL.md，frontmatter 里 name 和 description 两个字段都必须有，缺一个就直接解析失败、不出现在列表里
  • 调用方式是 /skill:<name>，不是 Claude Code 的 /<name>
  • 技能目录有变动会自动重新加载，不用重启客户端；新开会话最稳
  • Claude 的插件市场格式（.claude-plugin/plugin.json）Kimi Code 不能直接装，要手动把里面的 skills/ 子目录复制出来
  • npx skills add <仓库> --agent kimi-code-cli 是官方支持的安装方式，默认装到项目 .agents/skills/，加 --global 装到 ~/.agents/skills/

判断一个仓库能不能用，看四条就够了：

  1. 有没有 SKILL.md，frontmatter 有没有 name + description
  2. 有没有写死 ~/.claude/... 的路径或 Claude 专有工具名
  3. 脚本依赖的运行时你机器上有没有（Python、Node、ffmpeg、LibreOffice）
  4. 是不是只有 Claude 插件壳、没有裸 skills/ 目录

一、文档与数据表达

1. anthropics/skills —— 官方文档四件套

193,215 ★ · 最近提交 2026-11-06 · Apache-2.0

大白话：这是 Anthropic 把「Claude 帮你做 Word / PPT / Excel / PDF」背后那套本事开源了。给它一份 docx，它能改格式、插图表、套模板、处理修订和批注；给它一堆数据，它能生成带公式和样式的 xlsx；还能做 PDF 拆分合并、表单填写、扫描件 OCR。相当于给 agent 配了一个会用 Office 的实习生。

补了什么空白：mattpocock 教的是「怎么想、怎么写规格、怎么审代码」，它不会真的产出一个 .docx 或 .pptx 文件。这套补的是最后一公里：把内容变成能发出去的文件。

装进 Kimi Code：

git clone --depth 1 https://github.com/anthropics/skills.git /tmp/anthropics-skills
cp -r /tmp/anthropics-skills/skills/docx \
      /tmp/anthropics-skills/skills/pdf \
      /tmp/anthropics-skills/skills/pptx \
      /tmp/anthropics-skills/skills/xlsx \
      "D:/AppData/kimi-code/skills/"

四个目录各自带 SKILL.md 和 scripts/，复制过去就能被识别。装完用 /skill:docx、/skill:xlsx 试。同仓库还有 canvas-design、brand-guidelines、theme-factory，需要做视觉物料时可以一起拿。

坑与依赖：

  • 这些技能是照着 Claude 的沙箱写的，默认 docx、pptxgenjs、openpyxl、pandas 这些包已经预装。你的机器上大概率没有，第一次跑会报 require 或 import 失败，按提示 npm install / pip install 即可。
  • PDF 转换和 Excel 公式重算依赖 LibreOffice（soffice）。你机器上有 Office 和 WPS，但没有 LibreOffice；不装的话「转 PDF 看排版」「重算公式」这两类会退化，纯读写文件不受影响。
  • docx 技能还会用到 pandoc 和 pdftoppm，属于可选增强，缺了会跳过部分步骤。
  • 技能里写的是 python scripts/office/soffice.py，路径相对于 skill 自己目录，复制时整个文件夹一起搬，不要只拿 SKILL.md。

替代方案：huashu-excel（更懂中文表格业务），archify（图表）。

2. tt-a1i/archify —— 把任何东西画成能点的图

95,681 ★ · 最近提交 2026-11-12 · Apache-2.0

大白话：你跟它说「把这条链路画出来」或者「把这个方案讲清楚」，它生成的是一个能点、能展开、能切换明暗主题的单页 HTML，不是一张死图。支持架构图、时序图、流程图、数据流、状态机、ER 图、时间线等十来种。

补了什么空白：mattpocock 的 prototype 是「做个粗糙原型验证想法」，archify 是「把已经想清楚的东西讲给别人听」。一个对内，一个对外。

装进 Kimi Code：

npx -y skills@latest add https://archify.si --skill archify \
  --agent kimi-code-cli --global --copy --yes

不想用 npx 就手动复制：把仓库里的 archify/ 整个目录复制成 D:/AppData/kimi-code/skills/archify/，里面自带 SKILL.md、bin/、renderers/、schemas/。

坑与依赖：

  • 需要 Node 18+（你机器有 Node），渲染脚本用 ESM。
  • 产物是 HTML，不是 PPT；要放进汇报材料还得自己截图或另转。
  • 图复杂到一定程度，它仍会问你补信息；别指望一句话出终稿。
  • 官方安装器支持 claude-code、codex、cursor、opencode、github-copilot 这些 agent 名，kimi-code-cli 是 skills CLI 的标准 agent id，能装上；但 archify 自己的文档没点名 Kimi，装完建议先跑一次 /skill:archify 验证。

替代方案：anthropics/skills 里的 canvas-design（偏视觉海报），taste-skill（偏网页审美）。

3. blader/humanizer —— 把 AI 味改回人话

68,046 ★ · 最近提交 2026-11-10 · MIT

大白话：它专门删那些一眼就能看出是 AI 写的腔调：「不是 X，而是 Y」「让我们深入探讨」「这不仅是一次升级，更是一次重新定义」「说到底，真正重要的是……」——事实一个不改，只把话说得像人说的。判断标准来自维基百科编辑们总结的「AI 写作特征」。

补了什么空白：mattpocock 的 writing-for-agents 是「怎么写给 agent 看的文档」，管的是结构清晰、少歧义；humanizer 管的是「写给人看时别像机器人」。两件事。

装进 Kimi Code：这个最简单，单文件、零依赖。

mkdir -p "D:/AppData/kimi-code/skills/humanizer"
curl -fsSL https://raw.githubusercontent.com/blader/humanizer/main/SKILL.md \
  -o "D:/AppData/kimi-code/skills/humanizer/SKILL.md"

坑与依赖：

  • 语料偏英文，26 条特征是从英文写作里总结的。中文能不能有同样效果，得自己试；中文场景可以再叠一个 shuorenhua（2.6k 星，中文优先的去 AI 味）。
  • 它明确说了不负责绕过 AI 检测器，改完仍可能被判定为 AI 生成。要的是可读性，不是欺骗检测。
  • 会改语气，不会替你补事实；原文空洞，改完还是空洞。

替代方案：MrGeDiao/shuorenhua（2.6k，中文）、conorbronsdon/avoid-ai-writing（5.6k，审计式改写）。

4. 【破格】alchaincyf/huashu-excel —— 中文表格分析全流程

462 ★ · 最近提交 2026-11-04 · MIT

大白话：一个中文的「数据分析师傅」：先体检脏表（重复行、空值、口径不一致、单位混用），再清洗、定口径、算指标、对账，最后出报告。它反复强调一件事：让算出来的数字经得起追问。不是教你怎么点 Excel，是教你怎么判断一个数靠不靠谱。

补了什么空白：官方 xlsx 技能管的是「怎么读写文件、怎么写公式、怎么保格式」，不管「这个数对不对、口径有没有问题」。你手上那些系统导出表、对账表，缺的正好是后者。

装进 Kimi Code：整个仓库复制成一个 skill 目录。

git clone --depth 1 https://github.com/alchaincyf/huashu-excel.git /tmp/huashu-excel
cp -r /tmp/huashu-excel "D:/AppData/kimi-code/skills/huashu-excel"

坑与依赖：

  • 星标只有 462，远低于 5k 门槛，作者个人维护，没有评测集。这是破格收录，按需自取。
  • 依赖只有 openpyxl，很轻。
  • 话术和案例偏中文业务场景（电商、运营、财务对账），做技术数据时部分章节用不上。
  • 和官方 xlsx 技能同时装不冲突，但两个都会被模型自动选中，建议在 description 里分清使用场景，或者只留一个。

替代方案：anthropics/skills 的 xlsx（更通用、更稳）。

二、调研与知识管理

5. Graphify-Labs/graphify —— 把一文件夹资料变成知识地图

146,215 ★ · 最近提交 2026-11-11 · 未标注 License（用前确认）

大白话：把一个文件夹丢进去——代码、PDF、Markdown、截图、白板照片都行——它读完给你画一张关系图：哪些概念连着哪些、哪些是枢纽、哪些连接出乎意料。产物包括一个能点能搜的 graph.html、一个能直接当 Obsidian 库打开的目录、一份 GRAPH_REPORT.md，以及一个 graph.json。以后问问题不用重读原件，查图就行。

补了什么空白：mattpocock 的 research 是「去外面查资料，写成一篇带引用的 md」；graphify 是「把你已经有的资料变成可查询的结构」。一个向外，一个向内。

装进 Kimi Code：

pip install graphifyy
# 手动装 skill：注意仓库里文件名是小写 skill.md
mkdir -p "D:/AppData/kimi-code/skills/graphify"
curl -fsSL https://raw.githubusercontent.com/Graphify-Labs/graphify/main/skills/graphify/skill.md \
  -o "D:/AppData/kimi-code/skills/graphify/SKILL.md"

graphify install 默认往 ~/.claude/skills 写，Kimi 用户建议手动复制，避免装错地方。

坑与依赖：

  • PyPI 包名暂时是 graphifyy（graphify 这个名字还在收回），CLI 命令仍叫 graphify。
  • 需要 Python 3.10+；Windows 上如果 graphify 命令找不到，把 %APPDATA%/Python/Python3xx/Scripts 加进 PATH，或者用 pipx install graphifyy。
  • 抽取概念要调 LLM（含视觉），大文件夹第一次跑会又慢又费 token；它有 SHA256 缓存，第二次只处理变动的文件。
  • 生成的图质量取决于资料质量，垃圾进垃圾出。

替代方案：karpathy-llm-wiki（更轻，纯 Markdown，不建图）。

6. mvanhorn/last30days-skill —— 最近 30 天，真实的人在说什么

67,353 ★ · 最近提交 2026-11-12 · MIT

大白话：想知道「最近大家到底怎么评价这个话题」，它同时去 Reddit、X、YouTube、TikTok、Hacker News、Polymarket、GitHub 捞帖子，按点赞、转发、投注金额这些真实互动排序，再让 agent 综合成一份带链接的简报。它不搜「编辑认为重要的」，搜「人用注意力投票投出来的」。

补了什么空白：mattpocock 的 research 找的是高可信一手资料（官方文档、论文、源码），适合「查事实」；last30days 找的是舆情和体感，适合「看风向」。两者互补，不是替代。

装进 Kimi Code：

git clone --depth 1 https://github.com/mvanhorn/last30days-skill.git /tmp/last30days
cp -r /tmp/last30days/skills/last30days "D:/AppData/kimi-code/skills/last30days"

坑与依赖：

  • 需要 Python 3.12+、Node、yt-dlp；YouTube 搜索和字幕靠本机 yt-dlp，不用 key。
  • Reddit、HN、Polymarket、GitHub 零配置可用；X、YouTube 补量、TikTok、Instagram 要走 ScrapeCreators，免费额度 1 万次，之后按量付费。
  • 中文平台覆盖弱：小红书、微博、B 站都没有，做中文舆情会明显偏科。
  • 输出有强制格式（第一行必须是 🌐 last30days · ... 的 badge），不喜欢要自己改 SKILL.md。
  • 它靠 CLAUDECODE / CURSOR_AGENT 环境变量判断渲染方式，Kimi 下两者都没设，会走「显示完整 URL」的默认分支，正好适合你。

替代方案：mattpocock 的 research（免费、慢、更可信）；Graphify（分析已有资料）。

7. Leonxlnx/taste-skill —— 给 agent 装一点审美

113,663 ★ · 最近提交 2026-11-08 · MIT

大白话：做落地页、官网、产品页时，它会管配色、字号层级、留白、真实照片、动效节奏，还会用真浏览器截图自检，专门防那种「一眼 AI 生成」的塑料感。它内置一整套设计系统，不是给你十个方案让你选。

补了什么空白：mattpocock 的 prototype 只关心「这个交互能不能验证想法」，不管好不好看。taste 管的是「拿出去能不能见人」。

装进 Kimi Code：

npx skills add https://github.com/Leonxlnx/taste-skill \
  --skill "design-taste-frontend" --agent kimi-code-cli --global

手动装：复制 skills/taste-skill/ 整个目录到 D:/AppData/kimi-code/skills/。

坑与依赖：

  • 需要 Node 22+ 和 Chrome / Edge / Chromium（你机器有 Chrome）；它会调浏览器截图做视觉检查。
  • 技能内部注册名是 design-taste-frontend，不是文件夹名 taste-skill，调用时用 /skill:design-taste-frontend。
  • 偏营销站、公司站、产品页；做后台管理系统、数据大屏未必合适。
  • 会强推一套设计系统，和你现有品牌规范冲突时要手动压。

替代方案：Nutlope/hallmark（53.5k，反 AI 味设计），anthropics/skills 的 canvas-design。

8. virgiliojr94/book-to-skill —— 把一本书变成随取随用的手册

37,626 ★ · 最近提交 2026-11-08 · MIT

大白话：丢一本技术书（PDF、EPUB、DOCX、HTML、Markdown 都行），它把书里的框架、心智模型、原则、技巧、反模式抽出来，做成一个 skill。以后干活时 agent 能直接引用这本书的方法，而不是每次重新翻 PDF。

补了什么空白：mattpocock 的 teach 是「分多轮教你一个概念」，book-to-skill 是「把一本书固化成可调用的知识」。一个过程，一个产物。

装进 Kimi Code：复制整个仓库根目录（SKILL.md、book_to_skill/、scripts/、references/ 要一起）。

git clone --depth 1 https://github.com/virgiliojr94/book-to-skill.git /tmp/book-to-skill
cp -r /tmp/book-to-skill "D:/AppData/kimi-code/skills/book-to-skill"

坑与依赖：

  • 仓库带 pyproject.toml，解析 PDF/EPUB 需要 Python 依赖，第一次运行会提示装包；MOBI/AZW 还要 Calibre。
  • 书越长越慢，一本 500 页的书可能要跑很久，token 消耗不小。
  • 产出是「提炼版」，细节会丢；它适合当索引和提醒，不适合替代原书。
  • 有中文 README，对中文书支持要看实际解析效果。

替代方案：karpathy-llm-wiki（自己喂资料建 wiki），obsidian-skills（笔记库）。

9. obsidianmd/obsidian-skills —— Obsidian 官方出的 7 个技能

51,723 ★ · 最近提交 2026-11-11 · MIT

大白话：Obsidian 官方维护的一套技能，让 agent 会写 Obsidian 格式的笔记（双链、callout、frontmatter 属性）、会画 JSON Canvas 白板、会用 Obsidian CLI 管库；其中 defuddle 能把网页正文干净地抠成 Markdown，knap 能用 JSON/CSV 批量渲染模板。

补了什么空白：mattpocock 的文档是写给 agent 看的（规格、ADR、术语表）；这套是写给你自己的笔记库用的。方向相反。

装进 Kimi Code：复制 7 个技能目录。

git clone --depth 1 https://github.com/obsidianmd/obsidian-skills.git /tmp/obsidian-skills
cp -r /tmp/obsidian-skills/plugins/obsidian/skills/* "D:/AppData/kimi-code/skills/"

七个技能：obsidian-markdown、obsidian-bases、json-canvas、obsidian-cli、obsidian-headless、defuddle、knap。

坑与依赖：

  • 你机器上没装 Obsidian，所以 obsidian-cli、obsidian-headless、obsidian-bases 的核心价值用不上；能独立用的是 defuddle（网页转 Markdown）和 knap（模板批量生成）。
  • 想发挥完整价值，得先装 Obsidian 桌面端并建一个 vault。
  • 官方文档写的是 Claude Code / Codex / Cursor 的装法，Kimi 走手动复制最稳。

替代方案：karpathy-llm-wiki（纯文件，不依赖客户端）。

10. 【破格】Astro-Han/karpathy-llm-wiki —— 让 agent 替你养一个 wiki

2,728 ★ · 最近提交 2026-07-23 · MIT

大白话：照 Karpathy 的思路，建两个目录：raw/ 放原始资料（只读不改），wiki/ 放 agent 编译出来的词条。你往里丢东西，agent 负责消化、改写、互链、补索引。时间越长，wiki 越厚，问问题时查 wiki 就行。

补了什么空白：mattpocock 的 domain-modeling 是给代码库建术语表和 ADR；这个是给你读过的所有东西建词条。一个服务项目，一个服务你自己。

装进 Kimi Code：复制整个仓库根目录（SKILL.md、references/、scripts/）。

坑与依赖：

  • 星标 2.7k，低于门槛，破格收录；2026-07 之后没再更新。
  • 没有自动化评测，效果取决于你喂什么、喂多少。
  • 和 Graphify 的区别：这个产出是给人读的 Markdown wiki，Graphify 产出是给机器查的图 + 报告。两个都装不冲突，但会抢同一批资料。

替代方案：Graphify（结构化查询），obsidian-skills（有客户端时更好用）。

11. ayghri/i-have-adhd —— 让回答「能直接执行」

60,902 ★ · 最近提交 2026-10-19 · MIT

大白话：它假定读你回答的人注意力有限，于是强制 agent：先给下一步动作、多步任务编号、每轮复述当前状态、砍掉跑题、给具体时间估计、把进展做得看得见。不是把回答变短，是把回答变得能动手。

补了什么空白：mattpocock 管的是「做什么、怎么做对」，完全没管「回答长什么样」。这条直接改变你每天看输出的体验，而且不绑项目。

装进 Kimi Code：这个仓库原生支持 Kimi——根目录有 kimi.plugin.json，里面写着 “ADHD-friendly output shaping for Kimi Code CLI”。

git clone --depth 1 https://github.com/ayghri/i-have-adhd.git /tmp/i-have-adhd
cp -r /tmp/i-have-adhd/skills/i-have-adhd "D:/AppData/kimi-code/skills/"

坑与依赖：

  • frontmatter 里 disable-model-invocation: true，模型不会自动启用，要你手动 /skill:i-have-adhd；开了之后会一直生效，直到你说 “stop adhd mode”。
  • 有人会觉得每轮复述状态很啰嗦；它是刻意为之，不适合所有人。
  • 纯提示词，零依赖，删掉就恢复原样。

替代方案：同类很少；不喜欢就用一句话规则代替（「先给结论，再给步骤，每步不超过三行」）。
